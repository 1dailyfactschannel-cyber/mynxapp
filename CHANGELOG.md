# Changelog

## [1.3.1] - 2026-09

### Все фичи пришли в расширение: Health, категории с drag&drop, импорт CSV, автобэкап, favicon, a11y

Приложение 1.3.1 и расширение **1.0.5**. Новые возможности расширения опираются на новые
IPC-действия в десктопе — пароли по-прежнему не покидают ПК.

**Health-вкладка в попапе**
- Расчёт выполняется в десктопе (IPC `health`): балл 0–100, средняя сила, средний возраст пароля,
  списки «пора ротировать» / слабые / повторяющиеся / без 2FA — **ни одного пароля в ответе**,
  только метаданные и флаги (`src-tauri/src/ipc.rs`)
- Порог ротации 90/180/365 дней, спарклайн тренда (снапшоты раз в день в `chrome.storage.local`,
  до 90 точек), дельта за 7 дней
- Экспорт CSV-отчёта (UTF-8 BOM; пароли не включаются — их нет даже в данных отчёта)

**Категории и drag & drop в попапе**
- Вкладка All: чипсы категорий (фильтр), перетаскивание записи на чипс переносит её в категорию
  (новые IPC `list-all` и `update-entry`; правится только `category`/`favorite` записи)
- Клавиатурная альтернатива DnD: кнопка «📁 Move to category» на каждой записи открывает
  поповер со списком категорий и созданием новой

**Импорт CSV прямо из попапа**
- Chrome Passwords и Bitwarden CSV: автоопределение по заголовкам, парсинг в попапе, дедупликация
  на десктопе (нормализованный домен + username) → сводка «Imported N, skipped M dups»;
  крупные файлы дробятся на пачки по 500 записей (лимит натив-хоста 1 МБ)

**Расписание автобэкапа расширения**
- `chrome.alarms` → IPC `backup`: бэкап активного хранилища теми же настройками, что и фронтовый
  шедулер (путь/лимит копий синхронизируются новой командой `set_ipc_backup_prefs` в App.tsx)
- Пресеты 15м / 1ч / 6ч / 1д / 7д, статус последнего бэкапа, «Back up now»; ошибка — нативное
  уведомление, успех — тихо (alarm восстанавливается после рестарта service worker)

**Favicon-автозаполнение**
- Иконки в списке Site/All/Saved и в дропдауне автозаполнения на страницах; фоновый fetch
  (DuckDuckGo → Google s2, host_permissions), кэш data:URL в `chrome.storage.session`
  (до 300 иконок, чистится при закрытии браузера); тумблер «Show site favicons»

**Список и внешний вид**
- **Виртуализация вкладки All**: оконный рендер с overscan — тысячи записей скроллятся без деградации
- Режимы плотности Compact / Cozy / Spacious (высота строки виртуального списка подстраивается)
- Микро-анимации: стаггер-появление строк и чипсов, анимированный score-ring; пустые состояния
  с SVG-иллюстрациями (поиск, сайт, корзина captures, health, папка)

**Accessibility**
- Полная клавиатурная навигация попапа: tablist со стрелками, roving tabindex по спискам
  (↑/↓/Home/End), видимый focus-ring, ARIA-роли (tab/tabpanel/list/listitem/switch)
- Дропдаун автозаполнения — listbox-паттерн: ↑/↓/Home/End, Enter/Space, aria-activedescendant,
  иконка-кнопка получила role="button" и работу с клавиатуры
- High-contrast режим, масштаб шрифта 85–130% (rem), reduce-motion (настройка + `prefers-reduced-motion`)

**Passkeys** — управление по-прежнему в десктопе (Passkeys-раздел 1.3.0); попап и настройки
поясняют это, подсказка показывается на сайтах без сохранённых логинов.

- Прочее: генератор получил индикатор силы (порт `calculateStrength`), записи, сохранённые
  расширением, теперь получают поле `strength` (оценка на Rust-стороне идентична фронтовой)
- Расширение 1.0.4 → **1.0.5** (`permissions: +alarms`, `host_permissions` для иконок)

## [1.3.0] - 2026-09

### Крупный релиз UX: drag&drop, passkeys, Health 2.0, виртуализация и доступность

**Организация хранилища**
- **Drag & drop записей в категории**: карточку записи можно перетащить на категорию в сайдбаре — запись переносится (`src/lib/dnd.ts`, HTML5 DnD без зависимостей, подсветка цели)
- **Сортировка категорий**: пользовательские категории переупорядочиваются перетаскиванием в сайдбаре или стрелками ↑↓ в «Управлении категориями»; порядок хранится в persist (`order`)
- **Сортировка вложений и папок**: файлы переупорядочиваются drag&drop внутри папки и переносятся перетаскиванием в папку дерева (и на «Корень»); папки сортируются drag&drop среди соседей

**Favicon-автозаполнение**
- Иконки сайтов подтягиваются автоматически при добавлении записи (QuickAdd) и по кнопке в редакторе записи; при смене URL иконка обновляется
- Новая Rust-команда `fetch_favicon` (`src-tauri/src/favicon.rs`): CSP webview не пускает наружу — качает нативный слой (DuckDuckGo → Google s2), кэш в памяти на сутки, лимит 300 КБ, таймаут 6 с; фронтенд кэширует data: URL и хранит в поле записи (`Entry.favicon`) внутри зашифрованного vault-файла
- Настройка «Подтягивать favicon сайтов» (вкл. по умолчанию)

**Виртуализация списка + режимы плотности**
- `content-visibility: auto` на карточках — список из тысяч записей скроллится без деградации (рендеринг вне вьюпорта пропускается)
- Три режима плотности: «Компактно / Уютно / Просторно» (настройки → Внешний вид) — меняют отступы, размеры иконок и межстрочные промежутки

**Health-панель 2.0** (`src/lib/health.ts`, переработанный HealthDashboard)
- **Возраст пароля по дате последней смены** (passwordHistory → createdAt → updatedAt), средний возраст по хранилищу
- **«Пора ротировать»**: отдельная секция + настраиваемый порог 90/180/365 дней
- **Тренд балла**: ежедневные снапшоты в localStorage (до 90), спарклайн и дельта за 7 дней
- **Экспорт отчёта**: CSV (UTF-8 BOM, пароли не включаются никогда) и PDF через печать из скрытого iframe (кириллица корректна, без jsPDF)
- Итоговый балл теперь учитывает штрафы за повторы и просрочку ротации

**Passkeys (FIDO2)** — флагманская фича
- Менеджер passkey-учётных данных: пары ключей ECDSA P-256 (ES256) генерируются WebCrypto, credential ID 32 байта (`src/lib/passkey.ts`)
- Хранение — в том же шифрованном persist-хранилище, что и вложения (AES-256-GCM); приватные ключи не покидают устройство
- UI: раздел «Passkeys» в сайдбаре (`PasskeysView`) — создание (rpId + username), связка с записями по домену, self-test (подпись + проверка), экспорт/импорт JSON с дедупликацией по credentialId
- Раздел «Passkeys» в сайдбаре показывает живой счётчик

**Импорт: +6 форматов, дедупликация при слиянии** (`src/lib/import.ts`, `src/lib/dedupe.ts`)
- Новые форматы: 1Password (JSON v8), KeePassXC (JSON), LastPass (CSV), Dashlane (CSV), Proton Pass (CSV), Firefox (CSV) — итого 11 + автоопределение
- **Дедупликация**: перед импортом черновики сверяются с хранилищем (host+username → title+username → host+title), показывается число найденных дублей и стратегия: «Слить» (заполнить пустое, оставить более сильный пароль, объединить кастомные поля) / «Пропустить» / «Обе записи»; после импорта — сводка «Слито/Пропущено дублей»

**Расписание автобэкапа**
- Статус последнего бэкапа в настройках: время + успех/ошибка; кнопка «Сделать сейчас»
- Пресеты интервала: 15м / 1ч / 6ч / 1д / 7д (слайдер остался)

**Микро-анимации и пустые состояния**
- Новый компонент `EmptyState` с анимированными SVG-иллюстрациями (поиск, категория, корзина, вложения, passkeys, щит) — для пустых списков записей и вложений
- Стаггер-появление карточек записей, статик-иконка при перетаскивании

**Доступность (a11y)**
- **Полная клавиатурная навигация списка записей**: ↑/↓/Home/End/Enter/Space, видимый focus-ring (`:focus-visible`), карточки — фокусируемые кнопки с aria-label
- **Высокая контрастность**: тумблер в настройках + CSS-переопределения (жёстче границы, плотнее текст, стекло без блюра)
- **Масштаб шрифта** 85–130% (настройки → Внешний вид; масштабируется через rem)
- **Уменьшенная анимация**: учитывается системная `prefers-reduced-motion` + собственный тумблер

- Тесты: +28 (dedupe, health, passkey — 43 всего), tsc без ошибок
- Версии: приложение 1.2.5 → **1.3.0**; расширение остаётся 1.0.4

## [1.2.5] - 2026-09

### Канонический ID расширения — присвоенный Chrome Web Store

- **Store-ID `kjgmcffggjpmghjmhkhdiandaoefkmpb` (присвоен Google) стал каноническим**: обновление загружается в уже существующий item магазина, и версия из стора устанавливается именно под этим ID
- **`allowed_origins` натив-хоста теперь содержит оба ID**: store-ID (`kjgmcff…`) + dev-ID unpacked-сборки (`falikbn…`, производный от ключа в manifest.json) — нативный месседжинг работает «из коробки» и для версии из магазина, и для unpacked-установки (`src-tauri/src/native_host_reg.rs`, `native-host/register-native-host.ps1`, шаблон `native-host/com.matt.mynx.native.json`)
- **Webstore-пакет без `"key"`**: `mynx-extension-<v>-webstore.zip` больше не содержит вшитый ключ — магазин хранит ключ item с первой загрузки, и загружать наш не нужно; полный `mynx-extension-<v>.zip` для ручной установки по-прежнему с ключом, поэтому unpacked-ID стабилен независимо от пути папки
- `scripts/build_store_package.py`: зафиксированы оба ID, добавлена проверка соответствия ключа dev-ID (защита от случайной перегенерации `store/extension-key.pem`) и опция `--version` для быстрого бампа, если магазин отклонит загрузку по версии
- Версии: приложение 1.2.4 → **1.2.5**; расширение остаётся 1.0.4

## [1.2.4] - 2026-09

### Связь с расширением «из коробки» — без ручных скриптов

- **NSIS-инсталлятор регистрирует натив-хост сам**: новый `installerHooks` (`src-tauri/windows/installer-hooks.nsh`) при установке прописывает HKCU-ключи `NativeMessagingHosts` для Chrome / Edge / Chromium / Brave / Canary → при первом запуске браузера связка уже настроена; при удалении приложения ключи и манифест зачищаются (`NSIS_HOOK_PREUNINSTALL`)
- **Приложение самовосстанавливает регистрацию** (`src-tauri/src/native_host_reg.rs`, вызов в setup): при каждом запуске перезаписывает манифест хоста (`%LOCALAPPDATA%\Mynx\native-host\com.matt.mynx.native.json` — UTF-8, абсолютный путь к sidecar, стабильный ID расширения в `allowed_origins`) и те же HKCU-ключи; лечит перебитые ключи и обновления поверх старых версий, при отсутствии sidecar — тихий skip с записью в лог
- Манифест генерирует именно Rust-код (UTF-8): NSIS `FileWrite` в Unicode-сборке пишет UTF-16, который Chrome не читает — поэтому инсталлятор пишет только реестр
- `register-native-host.ps1` больше не нужен обычным пользователям — остаётся инструментом ремонта и для кастомных ID (`-ExtensionId`)
- Версии: приложение 1.2.3 → **1.2.4** (расширение остаётся 1.0.4 со стабильным ID `falikbndiimjeolnkclmifhgobmghhfe`)

## [1.2.3] - 2026-09

### Нативный хост для браузерного расширения

- **Нативный хост в инсталляторе**: `mynx-native-host.exe` теперь входит в состав NSIS-установщика как sidecar (`bundle.externalBin`) и ставится в `%LOCALAPPDATA%\Mynx\` — раньше бинарь хоста вообще не поставлялась, из-за чего расширение всегда показывало «Mynx desktop is not running»
- **`register-native-host.ps1`** — скрипт разовой регистрации натив-хоста: сам находит exe, генерирует манифест с правильным путём и **ID расширения пользователя** в `allowed_origins`, прописывает HKCU-ключи для Chrome / Edge / Chromium / Canary (прав администратора не нужны). Заменяет сломанный `register.reg` с захардкоженными личными путями автора (`D:\Kimi проекты\...`, `C:\Users\Matt\...`) и чужими ID расширений
- Релиз публикует отдельным ассетом `mynx-native-host.exe` для установки без переустановки приложения
- Документация: extension/README.md и USER-GUIDE §7 переписаны под новый сценарий установки

### Расширение (1.0.4) — исправление позиционирования inline-иконок, стабильный ID и пакет для Chrome Web Store

- Иконки автозаполнения больше не «уплывают» и не перекрывают иконки сайта: перевод на `position:fixed` + координаты вьюпорта (не зависят от `transform`/`filter`-контейнеров страницы и скролла), принудительное перепозиционирование при каждой мутации DOM и скролле любых контейнеров (capture + rAF-throttling), `visualViewport`
- Адаптивный отступ под иконки сайта: паддинг («глаз» и т.п.) пересчитывается при каждом скане, а не замеряется один раз — иконка Mynx больше не наслаивается на появившиеся позже элементы
- Дропдаун аккаунтов следует за своим полем, не вылезает за правый край и раскрывается вверх, если снизу нет места; иконки скрываются, когда поле уходит за вьюпорт
- Контент-скрипт теперь исполняется и во вложенных фреймах (`all_frames`) — работает автозаполнение в логин-виджетах внутри iframe
- **Стабильный ID расширения**: в `manifest.json` вшит публичный ключ (`"key"`) — ID теперь одинаков у unpacked-сборки и версии из магазина: `falikbndiimjeolnkclmifhgobmghhfe`. Это снимает главную причину «Mynx desktop is not running»: `allowed_origins` натив-хоста больше не зависит от ID, сгенерированного по пути папки
- `register-native-host.ps1` больше не спрашивает ID: стабильный ID вшит в скрипт (`$StableId`), `-ExtensionId` нужен только для кастомных локальных сборок
- `native-host/com.matt.mynx.native.json` — шаблон манифеста хоста с уже прописанным стабильным ID
- Скрипт `scripts/build_store_package.py` собирает два пакета: чистый `mynx-extension-1.0.4-webstore.zip` (только файлы расширения) для загрузки в Chrome Web Store и полный `mynx-extension-1.0.4.zip` с натив-хостом и README для ручной установки
- Материалы листинга в `store/`: скриншоты 1280×800 (рендерятся из макетов `store/mock/`), промо 1400×560 и 440×280, описания и обоснования разрешений, политика приватности
- Приватный ключ `store/extension-key.pem` добавлен в `.gitignore`; храните его: перегенерация меняет ID и ломает нативный месседжинг у установленных копий

### Безопасность (закрытие аудита: 29 находок → 27 закрыто, 2 частично)

- **CI-гейт**: security.yml запускает `cargo test`, `cargo clippy --all-targets -- -D warnings` (без continue-on-error), `npm audit` (prod — блокирующий, dev — отчётный); новый workflow frontend-tests.yml (tsc + vitest), extension-pack.yml (zip по тегу), docs-build.yml (pandoc для tech-stack.docx); dependabot (npm/cargo/actions)
- **AAD-привязка (v2)**: шифротексты заголовка/payload/декоя/экспорта/keyfile/буфера привязаны к роли — трансплантация блоков между сейфами невозможна; старые сейфы читаются (legacy-fallback)
- **KDF**: параметры Argon2id из файла больше не паникуют на подделке — возвращается ошибка
- **Целостность сейфа**: сериализация всех записей (устранение гонки), fsync, атомарный rename с резервной копией `*.safepass.bak`
- **IPC**: named pipe создаётся с `FILE_FLAG_FIRST_PIPE_INSTANCE` (защита от squatting `\\.\pipe\mynx`)
- **Автозаполнение**: строгий eTLD+1-скоринг доменов — lookalike-домены (`evil-paypal.com`) больше не получают пароль
- **Вложения**: zustand-персист шифруется AES-256-GCM (ключ — неэкспортируемый CryptoKey в IndexedDB), plaintext-миграция
- **Ссылки записей**: фильтр схем — `javascript:`/`data:` не открываются, домены без схемы поднимаются до https
- **Автоблокировка**: продублирована в бэкенде — простаивающая сессия затирается даже при обходе фронтенд-таймера
- **Windows Hello**: ключ сессии хранится в Credential Manager зашифрованным (обёртка из подписи Microsoft Passport; без Hello-промпта обёртку не открыть), старые записи читаются и мигрируются
- **Логирование**: уровни INFO/WARN/ERROR + файл app_data_dir/logs/mynx.log с ротацией (5 МБ)
- **API-токен**: `Zeroizing` при ротации + команда `rotate_api_token`
- **Прочее**: LICENSE (MIT), SECURITY.md, CONTRIBUTING.md, чистка персональных путей из build-release.bat, README-бейджи, RELEASE-CHECKLIST (подпись + updater), TODO.md убран из репозитория, vitest-тесты (15: ссылки, шифрование вложений, паритет en/ru)

- **История паролей** — просмотр предыдущих паролей для каждой записи с датой изменения, показом/скрытием и копированием
- **Кастомные поля** — добавление полей: текст, скрытое, email, URL, число, дата. Кнопка «+» с выпадающим списком типов
- **Заметки** — поле заметок для каждой записи
- **Вложения с каталогами** — загрузка файлов до 300 МБ, дерево папок, просмотр изображений в миниатюре и полном размере
- **Корзина** — удалённые записи помещаются в корзину с настраиваемым сроком хранения, восстановлением и удалением навсегда
- **Поиск по содержимому** — поиск в заметках и кастомных полях, не только в title/username/url/tags
- **Авто-скрытие паролей** — автоматическое скрытие паролей и скрытых полей по таймауту из настроек
- **Сайдбар настроек** — двухколоночный layout с разделами: Безопасность, Горячие клавиши, Внешний вид, Данные, Расширение, Опасная зона
- **Горячая клавиша генератора** — `Ctrl+Shift+G` открывает генератор паролей
- **Горячая клавиша блокировки** — `Ctrl+Shift+L` немедленно блокирует хранилище

### Изменено

- **Дефолтный хоткей автоввода** — с `Ctrl+Shift+T` на `Ctrl+Shift+Y` (избежание конфликта с браузером)
- **Автоввод** — ожидание отпускания модификаторов перед началом ввода, реакция только на `Pressed`
- **Язык при первом запуске** — определение системной локали через `navigator.language`
- **Панель записи** — сдвинута ниже шапки окна (`top-10` вместо `top-0`)
- **Настройки** — переделаны на сайдбар с разделами

### Исправлено

- **Горячие клавиши** — добавлены разрешения `global-shortcut:allow-register/unregister/is-registered`
- **Перекрытие шапкой** — панель записи больше не перекрывается заголовком окна
- **Автоввод** — исправлена обработка состояния нажатия клавиши

### Техническое

- Обновлена модель данных `Entry`: `notes`, `customFields`, `passwordHistory`, `deletedAt`
- Добавлены настройки: `backupEnabled`, `backupIntervalMinutes`, `backupPath`, `backupKeepCount`, `trashRetentionDays`, `passwordHideSeconds`, `hotkeyGenerator`, `hotkeyLock`
- Добавлен zustand-store для вложений и папок
- Добавлена команда Rust `vault_backup` для автобэкапа
