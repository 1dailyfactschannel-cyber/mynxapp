# Mynx — Руководство пользователя

Mynx — полностью офлайн-менеджер паролей. Нет облака, синхронизации и подписок: хранилище — один зашифрованный файл на вашем компьютере, и только вы решаете, где он лежит и куда копируется. На Windows доступна вся функциональность (авто-ввод, Windows Hello, защита памяти); на Linux работает базовый режим — всё, кроме перечисленного.

Это руководство встроено в приложение: оно открывается кнопкой помощи на главном экране, поэтому всегда под рукой.

## 1. Первый запуск

1. При первом запуске откроется мастер создания хранилища (Onboarding).
2. Придумайте **мастер-пароль** — это единственный пароль, который нужно помнить. Восстановить его невозможно: Mynx не хранит его нигде.
3. Сохраните **Emergency Kit** — PDF с QR-кодом, содержащим технический ключ устройства (Device Key). Он понадобится для переноса хранилища на другой компьютер и для восстановления доступа. Распечатайте или положите в надёжное место.
4. После создания хранилище открыто, можно добавлять записи.

### Экран блокировки

При каждом запуске и после автоблокировки приложение просит мастер-пароль. Если включена биометрия (Windows Hello) — доступна разблокировка по лицу/отпечатку/PIN. Неудачные попытки ввода ограничиваются: после серии промахов приложение наращивает паузу перед следующей попыткой.

Закрытие окна (крестик) **не завершает** приложение — оно сворачивается в трей и по умолчанию блокирует хранилище, затирая ключи в памяти. Выход — через меню иконки в трее (Quit).

## 2. Хранилища (vaults)

Хранилище — один зашифрованный файл `.safepass`. Можно иметь несколько хранилищ (личное, рабочее, семейное): на экране блокировки — «Switch Vault», откроется список известных хранилищ, создание нового и открытие внешнего файла (например, с флешки).

Каждое хранилище полностью изолировано: свой файл, свой мастер-пароль, своя соль шифрования. Пароль от одного хранилища не открывает другое.

## 3. Записи

### Добавление

- **Быстрое добавление** — `Ctrl+Shift+A` из любого места (глобальная клавиша) или кнопка в интерфейсе.
- **Из браузера** — расширение само предложит сохранить логин после входа на сайт (см. раздел 7).
- Поля записи: название, логин, пароль, URL, категория, теги, заметки, TOTP-секрет, вложения.

### Организация

- **Категории** — Banking, Social, Work и свои собственные (Manage Categories).
- **Избранное** и **теги** — для быстрой фильтрации.
- **Поиск** — строка поиска или командная палитра `Ctrl+K` (мгновенный поиск по всем записям).
- **Корзина** — удалённые записи хранятся отдельно; в настройках задаётся срок автоочистки (по умолчанию 30 дней). Записи из корзины не видны расширению браузера.

### TOTP (двухфакторные коды)

В записи можно сохранить TOTP-секрет — Mynx покажет шестизначный код, обновляющийся каждые 30 секунд. Код копируется и подставляется автозаполнением вместе с логином.

### Генератор паролей

`Ctrl+Shift+G` — генератор с настройкой длины и наборов символов (заглавные, строчные, цифры, символы) и индикатором стойкости. Генератор также встроен в форму записи и в расширение.

### Аудит паролей (Health)

Панель Health оценивает хранилище целиком и показывает: **слабые** пароли (низкая стойкость), **повторяющиеся** (один пароль на нескольких записях), **старые** (давно не менявшиеся) и записи **без двухфакторной аутентификации**. Каждая группа — готовый список «что обновить».

### Импорт из других менеджеров

Настройки → Данные → Импорт: перенос из Bitwarden (JSON/CSV), 1Password (CSV), KeePass/KeePassXC (CSV) и Chrome (CSV). Формат определяется автоматически, папки/группы становятся категориями, разбор файла происходит локально — файл никуда не отправляется.

### Auto-Type (Windows)

`Ctrl+Alt+A` вставляет логин и пароль **имитацией клавиатуры** в любое приложение (Steam, RDP, VPN, терминал), а не только в браузер. Буфер обмена не используется — кейлоггеры и сканеры clipboard не видят пароль. Открывается окно выбора записи, далее Mynx «печатает»: логин → Tab → пароль → Enter.

Функция основана на Win32 API и доступна только на Windows; на Linux Mynx честно сообщит о недоступности.

### Защищённый буфер обмена

Копирование пароля — «слепое»: секрет шифруется и хранится только в памяти приложения, **системный буфер обмена не используется вовсе** — сканеры буфера и история Win+V не видят ничего. Вставка — по `Ctrl+Shift+V` (или вашей клавише): Mynx «печатает» секрет в активное поле имитацией клавиатуры, после чего одноразовый буфер очищается. Опционально (в демо-режиме браузера) используется обычный буфер с автоочисткой по таймеру и отключением системной истории.

## 4. Горячие клавиши

Все клавиши переназначаются в Настройки → Горячие клавиши.

| Клавиша | Действие |
|---|---|
| `Ctrl+Shift+A` | Быстрое добавление записи |
| `Ctrl+Alt+A` | Auto-Type (ввод в любое приложение) |
| `Ctrl+Shift+G` | Генератор паролей |
| `Ctrl+Shift+L` | Заблокировать хранилище |
| `Ctrl+Shift+V` | Вставка из защищённого буфера |
| `Ctrl+Shift+M` | Показать окно из трея (переназначается) |
| `Ctrl+K` | Командная палитра / поиск |

## 5. Безопасность

### Как зашифровано хранилище

- **XChaCha20-Poly1305** — шифрование содержимого.
- **Argon2id** — вывод ключа из мастер-пароля (memory-hard, устойчив к GPU-брутфорсу).
- **Device Key** — 128-бит технический ключ, генерируемый на вашем компьютере. Для расшифровки нужны и мастер-пароль, и device key: украденного файла хранилища недостаточно.

### Автоблокировка

- По таймауту бездействия (по умолчанию 5 минут).
- При сворачивании окна в трей (можно отключить).
- Вручную — `Ctrl+Shift+L`.

Таймаут продублирован на уровне ядра приложения: даже если кто-то обойдёт или «усыпит» интерфейсный таймер (сон системы, зависание окна), любой запрос секретов после простоя вернёт «хранилище заблокировано» и сотрёт ключи из памяти.

При блокировке ключи затираются в памяти (zeroize). На Windows приложение дополнительно запрещает создание дампов своей памяти (в том числе при сбоях — аварийный обработчик завершает процесс раньше, чем система успеет снять дамп) и вытесняет рабочий набор при выходе.

### Целостность хранилища

- Каждое сохранение проходит три ступени: запись во временный файл → принудительная запись на диск (переживает сбой питания) → атомарная подмена основного файла.
- Предыдущая версия хранилища всегда остаётся рядом — в файле `<имя>.safepass.bak`: если после сбоя текущая версия не откроется, её можно восстановить из копии.
- Все части файла криптографически привязаны к своей роли: подмена или перестановка блоков между хранилищами обнаруживается и блокируется при расшифровке.
- Вложения в локальном хранилище интерфейса шифруются (AES-256-GCM); ключ не покидает браузерное хранилище приложения.
- Ссылки записей открываются только по http/https — адреса с опасными схемами блокируются.

### Слой-обманка (Decoy)

Можно задать **второй пароль**, открывающий правдоподобное фиктивное хранилище. Ввод decoy-пароля на экране блокировки показывает обманку, не раскрывая существования настоящих данных. Настраивается в Настройки → Безопасность. Decoy-пароль обязан отличаться от мастер-пароля.

### Аппаратный ключ (флешка)

Хранилище можно дополнительно привязать к файлу-ключу на USB-флешке: без неё хранилище не откроется даже с мастер-паролем. Настройка — Настройки → Безопасность. Храните резервную копию файла-ключа: потеря флешки без бэкапа сделает хранилище недоступным.

## 6. Бэкапы и восстановление

### Автобэкапы

Настройки → Данные: включение, интервал, папка, глубина ротации (сколько последних копий хранить). Бэкап — зашифрованная копия файла хранилища.

### Ручной бэкап и экспорт

- Резервная копия — в любой момент из настроек.
- Экспорт — зашифрованный файл для переноса.

### Emergency Kit

Печатная форма с QR-кодом Device Key (открывается диалог печати — «Сохранить как PDF»; можно скачать и PNG). Нужен, чтобы:
- открыть хранилище на **другом компьютере** (файл хранилища + Emergency Kit + мастер-пароль);
- восстановить доступ при переустановке системы.

Без Emergency Kit перенос на новое устройство невозможен — это осознанное ограничение безопасности.

### Смена мастер-пароля

Настройки → Безопасность → Сменить пароль. Хранилище перешифровывается, старые бэкапы остаются под старым паролем.

## 7. Расширение для браузера

### Установка и связь с приложением

1. Установите десктопное приложение Mynx **1.2.4+** — оно само регистрирует нативный хост во время установки (и повторяет регистрацию при каждом запуске): манифест пишется в `%LOCALAPPDATA%\Mynx\native-host\`, ключи реестра — в HKCU для Chrome / Edge / Chromium / Brave. Никаких скриптов и ручных шагов не нужно.
2. Установите расширение Mynx из Chrome Web Store (поддерживаются Chrome и Edge) — ID расширения стабильный и уже вписан в регистрацию хоста.
3. Запустите десктопное приложение Mynx — расширение связывается с ним через защищённый локальный канал (named pipe на Windows, unix-сокет на Linux; доступ только вашей учётной записи).
4. Индикатор в шапке расширения:
   - **Offline** — приложение не запущено;
   - **Locked** — приложение работает, хранилище заблокировано;
   - **Unlocked** — готово к работе.

> Если связка всё же не появилась (нестандартная сборка браузера, кастомный ID расширения) — разовую регистрацию можно выполнить вручную:
>
> ```powershell
> powershell -ExecutionPolicy Bypass -File extension\native-host\register-native-host.ps1
> ```
>
> Скрипт сам найдёт хост и пропишет его для всех браузеров (прав администратора не нужны); кастомный ID передаётся через `-ExtensionId`.

### Подтверждение доступа (pairing)

При **первом** обращении к хранилищу (автозаполнение, поиск, сохранение) расширение запрашивает доступ:

1. В Chrome появляется уведомление «Confirm access in the Mynx desktop app».
2. Поверх окон открывается системный диалог Mynx «Запрос доступа» (на языке, выбранном в приложении).
3. Нажмите **«Разрешить»** — расширение получает ключ доступа и дальше работает молча.

Ключ действует **до перезапуска приложения Mynx**. После перезапуска подтверждение попросят снова — это защита от скрытого доступа других программ к вашим паролям.

### Как подбираются записи (безопасность автозаполнения)

Расширение подставляет логин только когда **домен сайта совпадает с доменом записи**: точное совпадение или поддомен того же сайта (`mail.google.com` получит запись для `google.com`). Похожие, но чужие домены (`evil-paypal.com`, `paypal.com.evil.io`) пароль **не получают вообще** — защита от фишинга. Если расширение «молчит» на привычном сайте — проверьте адресную строку: скорее всего, вы не на том домене.

### Вкладки расширения

- **Site** — учётные записи для текущего сайта: автозаполнение (Fill), копирование логина/пароля, кнопка **«+ Add login»** для ручного добавления записи (URL подставляется автоматически).
- **All** — все записи хранилища с поиском (пароли отсюда не показываются).
- **Generator** — генератор паролей (длина, наборы символов).
- **Saved** — логины, перехваченные при входе на сайты: просмотр, «Save to vault», отклонить.

### Иконка в полях ввода

На страницах входа Mynx показывает зелёный замок в поле логина/пароля. Клик — список подходящих учёток, выбор — мгновенное заполнение. Иконка встаёт левее служебных иконок сайта (например, «показать пароль»), не перекрывая их.

### Автосохранение

После входа на сайт с новым логином расширение запоминает его во временной памяти браузера (вкладка **Saved**, значок «+» на иконке расширения) и предлагает сохранить в хранилище одной кнопкой. Данные живут только в сессии браузера, на диск не пишутся.

## 8. Настройки

| Раздел | Что внутри |
|---|---|
| **Безопасность** | Автоблокировка, блокировка при сворачивании, очистка буфера, смена мастер-пароля, decoy-пароль, аппаратный ключ, биометрия |
| **Горячие клавиши** | Переназначение всех глобальных сочетаний |
| **Внешний вид** | Тема (тёмная/светлая/системная), язык, прозрачность «стекла» |
| **Данные** | Автобэкапы, ручной бэкап, экспорт, импорт из других менеджеров, автоочистка корзины |
| **Расширение** | Токен API и инструкция по установке расширения |
| **Опасная зона** | Удаление хранилища (с подтверждением паролем) |
